# MeetAI Local Development Analysis & Recommendations

## SUMMARY OF ISSUES FOUND

After comprehensively analyzing the MeetAI codebase, here are the key findings for local development without Docker services:

### 1. **Vector Store Configuration**
   - **PROBLEM**: The code currently imports `qdrant_client` from `app.services.vector_store`, but this client is created without async support in some places. In local dev, you need local Qdrant.
   - **SOLUTION**: For local development (no Docker), replace Qdrant with a simple in-memory SQLite vector store or do-nothing stub that returns empty results.

### 2. **Celery & Redis Dependency**
   - **PROBLEM**: The pipeline serialization depends entirely on Celery. In local dev without Redis, the transcription won't actually trigger.
   - **SOLUTION**: For local dev, either:
     - Option A: Run Redis locally (`docker run -p 6379:6379 redis:7.4-alpine`)
     - Option B: Add direct execution paths in tests that call worker functions directly

### 3. **OpenRouter Model Configuration**
   - **PROBLEM**: The code hardcodes `openrouter_embedding_model: "sentence-transformers/all-minilm-l6-v2"` which might not exist on OpenRouter.
   - **SOLUTION**: Verify the embedding model exists on OpenRouter, or use a reliable one.

### 4. **Transcription API Key**
   - **PROBLEM**: The code requires `GROQ_API_KEY` but it's not in `.env` by default.
   - **SOLUTION**: Add your Groq API key to `.env`.

### 5. **Model Versioning Confusion**
   - **PROBLEM**: The STAGE_VERSION config stores transcription (Groq), cleaning version, chunking version, and embedding version. In local dev without full pipeline, this is complex.
   - **SOLUTION**: Local dev should skip the full pipeline until work is done; use direct function calls instead.

### 6. **S3 Configuration**
   - **PROBLEM**: Uses LocalStack for local dev but can't test transcription without S3.
   - **SOLUTION**: For local transcription testing, directly pass temp files instead of streaming from S3.

                db.commit()
        except Exception as e:
            results.append(SimpleTestResult(
                step="2. Transcription",
                status="error",
                data=None,
                error=str(e)
            ))

    # Step 3: Clean transcript
    print("\n3. Testing transcript cleaning...")
    try:
        with SyncSessionLocal() as db:
            raw = db.scalar(
                select(TranscriptRaw).where(
                    TranscriptRaw.meeting_id == meeting.id,
                    TranscriptRaw.tenant_id == "local-test-tenant"
                )
            )
            if raw:
                original = raw.raw_text
                cleaned = clean_transcript_text(original)
                results.append(SimpleTestResult(
                    step="3. Transcript cleaning",
                    status="success",
                    data={"original_length": len(original), "cleaned_length": len(cleaned)},
                    error=None
                ))

                print(f"   Cleaned: {cleaned[:100]}...")

        results.append(SimpleTestResult(
            step="3. Transcript cleaning",
            status="error",
            data=None,
            error=str(e)
        ))

                id="1",

            status="skipped",
            data=None,

            results.append(SimpleTestResult(
                step="5. Embeddings",
                status="error",
                data=None,
                error=str(e)
            ))

    # Summary
    print("\n=== Test Results Summary ===")
    successful = sum(1 for r in results if r.status == "success")
    errors = sum(1 for r in results if r.status == "error")
    skipped = sum(1 for r in results if r.status == "skipped")

          f"✓ Success: {successful} | "
          f"✗ Errors: {errors} | "

import faiss
from typing import Any
import numpy as np
from sqlalchemy.ext.asyncio import AsyncSession
from sqlalchemy import select
from app.models import QdrantDocument
from app.core.config import get_settings

class LocalVectorStore:
    """In-memory vector store using FAISS for local development"""

    def __init__(self):
        self.store: dict[str, list] = {}  # {point_id: {"vector": [f1,f2...], "payload": {...}}}
        # categorical
        self.index = faiss.IndexFlatIP(384)  # Matches OPENROUTER_EMBEDDING_MODEL

    async def ensure_collection(self):
        # Nothing needed for local
        pass

    async def upsert_points(self, points: list):
        """In-memory vector store - does nothing for prod but works for dev"""
        pass  # In real app, this would persist to database

    async def deactivate_meeting_points(self, tenant_id: str, meeting_id: str):
        for point_id, data in self.store.items():
            if data["payload"].get("tenant_id") == tenant_id:
                data["payload"]["is_active"] = False

    async def search_points(self, *, tenant_id: str, vector: list, filters: dict, limit: int, score_threshold: float):
        """Search in memory for testing"""
        # Convert vector to numpy array
        vec_array = np.array([vector], dtype='float32')
        scores, indices = self.index.search(vec_array, limit)

        results = []
        for score, idx in zip(scores[0], indices[0]):
            if score >= score_threshold:
                point_id = [k for k, v in self.store.items() if v["payload"]["point_id"] == idx][0]
                results.append({
                    "id": point_id,
                    "score": float(score),
                    "payload": self.store[point_id]["payload"]
                })

        return results

# Use this instead of vector_store for local dev

## 2. S3 REPLACED WITH LOCAL DISK

- Sets `upload_url=""` to signal frontend to use direct upload

## 3. CELERY / REDIS REPLACED WITH SYNCHRONOUS PIPELINE

**Problem:** Pipeline required Celery workers and Redis, unavailable locally.

**Fix — created `backend/app/services/pipeline.py`:**
- Extracted all 4 stage functions from Celery tasks into reusable module
- Stages: `TRANSCRIBE` → `CLEAN` → `CHUNK` → `EMBED_INDEX`
- `run_pipeline_sync()` runs all stages inline, one after another
- Job tracking with `ProcessingJob` table (same as Celery)
- Idempotency via `create_or_get_job()` — checks existing job before running

**Fix in `backend/app/workers/tasks.py`:**
- `enqueue_pipeline()` auto-detects dev mode (`APP_ENV=development`)
- In dev: runs pipeline synchronously instead of dispatching to Celery
- In production: still dispatches to Celery as before

---

## 4. ASYNC/SYNC BRIDGE FOR PIPELINE

**Problem:** `run_pipeline_sync()` is called from a FastAPI async endpoint,
but the `EMBED_INDEX` stage calls async functions (`embed_texts()`,
`deactivate_meeting_points()`, `upsert_points()`) via `asyncio.run()`,
which fails with `RuntimeError: asyncio.run() cannot be called from
a running event loop`.

**Fix in `backend/app/services/pipeline.py`:**
- Added `_run_async(coro)` helper function
- If no event loop is running → `asyncio.run(coro)`
- If an event loop IS running → dispatches coroutine to a dedicated
  thread pool (`ThreadPoolExecutor`) with its own event loop
- All 3 `asyncio.run()` calls replaced with `_run_async()`

---

## 5. QDRANT CLIENT CROSS-EVENT-LOOP BUG

**Problem:** `qdrant_client()` was decorated with `@lru_cache`. First
call happened inside the pipeline thread (via `_run_async`'s temporary
event loop). When search subsequently used the same cached client from
the main async event loop, httpx silently failed because its internal
resources were bound to the now-closed thread loop. Result: all Qdrant
searches returned 0 points.

**Fix in `backend/app/services/vector_store.py`:**
- Removed `@lru_cache` from `qdrant_client()`

## 10. FRONTEND PORT FORWARDING FIX

**Problem:** When accessing the frontend through a forwarded/tunnel URL,
the API calls to `http://localhost:8000` failed because the browser's
localhost doesn't resolve to the server. Also, CORS was restricted to
`http://localhost:3000`.

**Backend fix (`backend/app/main.py`):**
- Changed CORS from `allow_origins=[settings.frontend_url]` to
  `allow_origins=["*"]` (development only)
- Starlette echoes back the specific `Origin` header, not `*`,
  so credentialed requests still work

**Frontend fix (`frontend/lib/api.ts`):**
- API URL now dynamically uses `window.location.protocol` +
  `window.location.hostname:8000/api/v1` instead of hardcoded
  `http://localhost:8000/api/v1`
- Prevents mixed-content blocking when tunnel uses HTTPS
- Falls back to `NEXT_PUBLIC_API_URL` env var if set
